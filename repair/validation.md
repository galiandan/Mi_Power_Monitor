## 隔离复现记录

### R01：实际时间与固定一秒假设

临时复制采样脚本，将 `/sys/class/powercap` 替换为临时模拟目录。通过临时 PATH 中的 `sleep` 实际等待两秒并更新能量文件。

- 初值：1,000,000 微焦耳。
- 终值：41,000,000 微焦耳。
- 命令整体耗时：约 2.02 秒。
- 当前输出：CPU 40.0W。
- 正确量级：约 20W。

整体耗时包含进程和其他采集开销，不能作为精确的单 Package 时间戳；这个测试用来证明延迟不被算法计入。

### R02：Package 与 psys 被相加

临时输入提供两个顶层域：`package-0` 为 20W、`psys` 为 80W。当前代码没有读取 `name` 文件，输出 CPU 100.0W。这里只模拟了该拓扑，没有声称本机存在 psys。

### R03：第二次读取无效

第一次提供有效能量值，第二次改为 `invalid`。脚本输出 CPU 0.0W，确认无效样本被当作可用零值。

### R04：串行采集

临时 HOME 下创建模拟 `~/.local/bin/mi-power-monitor-sensors` 和 `xiaomi-power`，分别等待一秒、两秒并输出合法 JSON。执行原始汇总脚本，约 3.03 秒后输出整批结果。没有修改真实用户的命令或配置。

### R06：备份解压内存

构造不包含真实凭据的 Android 备份，数据库成员为约 32 MiB 可压缩内容；压缩后约 31.9 KiB。在已安装的 `android_backup` 中使用与项目一致的 `stream=False` 调用，通过 `tracemalloc` 测得 Python 分配峰值约 77.5 MiB。

该测量只覆盖 Python 可追踪分配，不能当作 RSS，也不代表所有压缩/加密格式的峰值。未进行可能导致 OOM 的大体积压力测试。

上述 RAPL 临时脚本运行时仍可能读取机器真实的 NVIDIA 功率；GPU 数值没有用于 CPU 复现结论，也没有修改 GPU 设置。

## 修复后仍未覆盖

- 真实插座持续丢包、首包丢失、延迟响应、断网恢复。
- Plasma executable 引擎的具体重入/排队行为；不能据此宣称已经存在进程堆积。
- 连续数小时的 CPU、RSS、文件描述符、进程数及磁盘占用趋势。
- 浅色主题、HiDPI、54px 面板、不同缩放比例和字体的实际渲染；本轮只实测了 34px 深色主题面板。
- AMD、多个 CPU Package、包含 psys 的真实硬件。
- 异名主组、多用户账户、重启与驱动重载后的 RAPL 权限；本轮没有修改系统权限。
- 真实安装中断、KPackage 升级失败、完整卸载、卸载授权取消和桌面实例清理。
- 修复后的多种加密 Android 备份、接近资源上限的内存/磁盘压力测试。
- GitHub 分支保护、必需检查和自动合并的远端设置。

真实插座配置文件不存在，因此没有扫码、触碰 token 或发送插座查询。面板验收使用临时假读数，不改变系统权限或其他面板项目。

### Plasma 面板实机检查

在当前 Plasma 桌面临时安装组件包，用本机 mock 采集器返回 `83.4W / 21.2W / 37.1W`，并在真实 34px 高度面板中查看：

- Full 显示 `83W · CPU 21W · GPU 37W`，正常使用面板文字颜色和 Breeze accent 图标。
- Compact 显示总功耗和 CPU/GPU 数值，不显示标签。
- Total only 仅显示总功耗。
- 全部输入设为 unavailable，宽度在 5 秒缓冲期内保留，之后收缩为图标与 `--W`。
- 面板中可见文本和图标居中并适配当前高度；QDBus 返回的 geometry 数值不用于判定渲染，检查依据为实际桌面截图。

临时小组件、mock 命令链接、假数据和截图已移除；`kpackagetool6` 确认临时包已卸载，Panel 中临时实例已移除。该检查没有使用真实插座配置，也未验证高频连续数值变化、浅色主题、HiDPI 或 54px 面板。

## 修复后的回归顺序

1. **采集正确性**：用模拟输入验证时间差、Package 筛选、回绕、非法读数和部分失败。每种情况检查 JSON 的数值与 unavailable 语义。
2. **调度与超时**：模拟快慢来源、持续故障和晚到数据，检查输出时间戳、整轮耗时、终止行为和进程数。
3. **配置完整性**：对写入、刷新、替换分别注入错误，确保旧 token 配置可继续读取，且权限和临时文件处理正确。
4. **安装与回滚**：在隔离 HOME/XDG 路径中模拟命令，验证失败阶段不损坏旧版本、不复制开发残留、不误删未知文件。涉及系统权限和真实 Plasma 的步骤单独实机验收。
5. **备份资源占用**：使用多个规模的合成备份记录 RSS、峰值 Python 分配、临时磁盘峰值及结束后残留，验证资源增长受到约束。
6. **Plasma 实机**：在原生面板测试 full/compact/totalOnly、CPU/GPU 开关、长数字、失联恢复、主题和缩放，观察邻近项目是否移动。
7. **自动化门禁**：把必要且稳定的回归加入上游同步流程，用一个故意破坏接口的更新验证合并确实被阻止。

每次修复记录提交、执行的检查和结果。没有实测的项目继续标注未验证，不能用语法检查代替硬件或视觉验收。
