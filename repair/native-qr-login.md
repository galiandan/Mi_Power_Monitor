# Go 内置二维码登录迁移

日期：2026-09-26。

## 必要性

原安装流程在 Go 后端已构建后，仍为一次性扫码创建 venv、下载 pip 包、clone/fetch 外部工具；用户已遇到静默等待。新实现用 Go 标准库直接申请二维码、等待确认、获取云端会话和设备列表，不新增 Go 模块，不调用 Python 扫码或下载第三方执行脚本。旧 Python 工具作为手动兼容入口保留。

## 实现

- `--setup-cloud-qr`、`--region`、`--no-browser`、`--validate-config`。默认服务器提示 cn；all 模式提示并跳过不可用服务器。
- http.Client 有连接总等待上限，扫码按服务器 TTL（最多 300 秒）等待，整体流程最多 10 分钟；Ctrl+C 取消。CLI 错误不包含云端响应体、URL ticket、token 或 ssecurity。
- HTTPS 仅允许小米域名，重定向同样检查；云端响应最多 8 MiB。图片类型与尺寸先验证。
- 本地页面仅绑定 127.0.0.1 随机端口，使用随机路径，校验 Host，禁止缓存/跨框架嵌入；只显示二维码，不提供 token 或账号会话。登录结束关闭。
- 选定型号与多插座按序号选择；缺少有效 IP 时手动输入。仅保存选中插座配置：目录 0700、文件 0600、同目录临时文件 fsync/rename，拒绝符号链接目标。
- KDE 暂存构建现在复制全部生产 Go 源文件；上游同步复制第三方许可声明。
- 独立后端需发布新的 v1.1.0 二进制，旧 release 不支持新入口；安装器检测并拒绝不兼容发行包。

协议参考固定版本的 Xiaomi-cloud-tokens-extractor，并保留 MIT 许可和作者声明到 THIRD_PARTY_NOTICES.md。

## 验证与边界

Go vet、race 测试覆盖：独立 Python/PyCryptodome 生成的 RC4/signature 向量、模拟二维码申请/确认/STS Cookie/加密家庭与设备查询、型号筛选、URL 限制、随机本地页面与 Host 校验/关闭、多插座选择/不输出 token、旧配置保留/权限/符号链接及取消。KDE Python 30 项回归通过，扫码安装入口测试更新为内置模式。

已向真实小米端点成功申请二维码并启动本机页面；12 秒后主动取消，未进行账号确认、未读取真实设备列表、未保存真实 token。完整扫码登录仍需用户在手机确认；不能把模拟设备查询写成真实账号已验证。云协议不是稳定公开 API。超过单页上限且有分页标志时明确失败，避免静默漏选。

补充验收：真实 Go 暂存构建和隔离 HOME 安装通过（KPackage/DBus 模拟，硬件发现指向空目录），安装后命令具有 --setup-cloud-qr，未创建 .venv。发行包构建 linux/amd64、linux/arm64；amd64 二进制在 PATH 无 Python/git 等命令时完成配置验证。Go 共 12 项测试、race 检查通过。

## v1.1.1 登录结果反馈

不再在账号登录成功时立即关闭页面。浏览器轮询只包含状态/标题/说明的本地接口：等待扫码 → 登录成功 → 配置完成；账号已登录后的读取/保存错误显示“已登录，配置未完成”。自动更新页面标题并切换到 /result 路径，隐藏旧二维码。最终状态响应刷新到连接后关闭服务，未打开浏览器时最多等待 2 秒；页面停止轮询并保留结果。浏览器通常无权强制切换 KDE Wayland 的终端窗口，明确提示 Alt+Tab 返回，不伪装为已经完成安装。

新增状态机、结果路径、旧二维码失效、最终响应确认、取消等待测试；Go 14 项测试和 race 检查通过。本轮未执行实际浏览器/真实账号扫码验收。
