## 优先级与状态

P1：应优先解决，直接影响读数可信度或主要刷新体验。

P2：影响特定环境、故障恢复、安装完整性或资源安全。

“已复现”指在隔离输入下观察到问题；“代码确认”指控制流或接口不一致可以从源码确认；“待实机验证”表示最终表现依赖硬件、桌面或外部配置。复现过某个条件不代表所有用户都会触发。

1. 联合修复 R01—R03，先使 CPU 读数准确且可靠区分不可用。
2. 联合修复 R04—R05，统一采集时序、超时和过期策略。
3. 修复 R14、R07、R08、R15，建立可靠的配置写入与版本切换流程。
4. 修复 R09—R10，补全权限与卸载的失败恢复。
5. 修复 R06，限制备份导入的内存与存储消耗。
6. 修复 R11，再让自动同步依赖这些回归检查。
7. 修复 R12—R13，完成 Plasma 实机验收和安装体验。

独立后端的公共修改需要同步到 KDE 的 `backend/`，或通过经过验证的同步 PR 引入。CPU/GPU 采集及 QML 属于 KDE 仓库，不应错误地加入仅负责插座功率的后端接口。
